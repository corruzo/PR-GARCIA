# PRGARCÍA

Gestión de préstamos y cartera bimonetaria (USD/VES) con tasa BCV y soporte PWA: calculadora, clientes, préstamos con cronograma, pagos y abonos, mora, cobranza, contabilidad y reportes de diferencial cambiario.

Antes de usar los módulos de cartera hay que aplicar las migraciones de `supabase/migrations/` (ver `docs/CAMBIOS_SUPABASE.md`).

## Requisitos

- Node.js 22.5+
- npm

## Scripts locales

```bash
npm install
npm run dev
```

`npm run dev` levanta dos procesos: Vite en `http://localhost:5173` y la API local en `http://localhost:8787`.
La API usa SQLite nativo con WAL y guarda el archivo en `data/prestamo.sqlite`. Ese archivo está ignorado por Git.
Si el BCV no responde durante el desarrollo, la API usa `BCV_DEV_RATE` como semilla local y devuelve la última tasa guardada con la marca `stale: true`.

Para ejecutar solo la API local:

```bash
npm run dev:api
```

El contrato local es el mismo que en producción:

- `GET /api/bcv`: consulta el BCV oficial y persiste la tasa.
- `GET /api/bcv/latest`: devuelve la última tasa persistida.

## Backend Vercel

En Vercel, las mismas rutas serverless consultan el BCV y guardan la tasa en Supabase. No se usa SQLite en Vercel porque el filesystem de una función serverless no es persistente.

### Variables de entorno requeridas

```bash
SUPABASE_URL=tu_url
SUPABASE_SERVICE_ROLE_KEY=tu_clave
```

### Endpoint

- GET /api/bcv -> consulta la tasa oficial del BCV y la guarda en la tabla `tasa_bcv`
- GET /api/bcv/latest -> devuelve la última tasa almacenada

La ruta de actualización solo acepta GET y exige que Supabase esté configurado; nunca guarda una tasa EUR como USD ni confirma éxito si la persistencia falla.

### SQL sugerido

```sql
create table if not exists tasa_bcv (
	id bigint generated by default as identity primary key,
	tasa numeric not null,
	fuente text not null,
	fecha_hora timestamptz not null default now(),
	estado text not null default 'ok'
);
```

## Despliegue en Vercel

1. Conecta este repo a Vercel.
2. Agrega las variables de entorno de Supabase.
3. Haz deploy.
4. La ruta API queda disponible en tu dominio de Vercel.

El flujo recomendado es validar primero con SQLite local y luego desplegar el frontend y las funciones `api/` en Vercel conectadas a Supabase.
